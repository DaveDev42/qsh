# M24 홀펀칭 실제 망 캠페인

상태: 기준 확정, 회차 미실행. 회차는 사람이 돌리고 §7에 기록한다.

## 1. 목적과 지위

ADR-0054 결과 절이 이 문서를 요구한다. 홀펀칭이 실제 망의 공유기와 통신사 NAT에서 열리는지, 열리지 않으면 어떤 사유로 포기하는지를 A–B 쌍마다 기록한다. CI는 가상 망(`punch_accept::punch_route_nat_matrix`, netsim의 NAT 상자 25쌍)과 리눅스 커널 NAT 대조(`scripts/netns/punch.sh`, CI의 `punch-netns`)로 같은 동작을 잰다. 하지만 상용 공유기의 매핑 정책, 통신사 CGNAT, 회사 방화벽, IPv6 전용 망은 흉내 낼 수 없어서 이 캠페인만 준다. ADR-0054는 netsim의 NAT 모델이 실제 공유기와 다를 수 있다는 위험을 남겼고, 이 캠페인이 그 간격을 줄이는 자리다.

지위는 마일스톤 DoD가 아니다. ADR-0054 결과 절이 DoD에 넣지 않는다고 못박았다. 판정 기준(§6)은 회차를 돌리기 전에 고정하며 사후에 조정하지 않는다. 기준을 못 맞춘 쌍은 §8의 처분을 따른다.

기대치도 미리 적어 둔다. 양쪽이 목적지마다 포트를 바꾸는 NAT의 조합과 symmetric 대 port-restricted 조합은 열리지 않는다(ADR-0054 남는 위험). 그런 쌍이 `timeout`으로 끝나는 것은 실패가 아니라 기대한 동작이다. 판정은 열렸는지보다 "열리면 제때 서고, 닫히면 8초 안에 사유와 함께 끝나는지"를 본다.

## 2. 토폴로지와 전제 조건

| 역할 | 장비 | 실행하는 것 |
|---|---|---|
| R (중개자) | 공인 주소나 열린 UDP 포트를 가진 상시 장비 | `qsh listen`. 두 장비가 모두 이 주소로 닿는다. |
| B (target) | NAT 뒤 장비 | `qsh serve --to R` (역방향 등록). 펀칭 대상은 이 등록이 있는 host로 한정된다(ADR-0054). |
| A (client) | B와 다른 망의 장비 | 펀칭을 시도하는 `qsh` 명령 |

전제는 이렇다.

- R, A, B는 서로 pin돼 있다. A에는 R이 주소와 함께 pin돼 있고 B의 pin에 `qsh trust rendezvous <B> <R>`로 중개자가 적혀 있다(또는 명령마다 `--rendezvous <R>`을 준다). B는 R에 등록돼 있다.
- R과 B의 `acl.toml`·pin role이 `host.punch`를 허락한다. `none` 말고는 모든 role이 이 action을 준다(`docs/CLI.md` §6.11).
- A에서 B로 가는 직접 경로가 없어야 한다. 직접 경로가 서면 펀칭이 필요 없으므로 쌍을 기록하는 의미가 없다. 확인은 `qsh doctor <B>`가 `punch_succeeded`, `punch_failed`, `punch_no_rendezvous` 가운데 하나를 내는지로 한다. 직접 경로가 있으면 `data.punch`가 없다.
- 장비마다 이 캠페인 전용 프로필을 쓰고 `key_store = "file"`로 둔다(`docs/campaigns/m2-mobility.md` §2 3번과 같은 이유).
- `qsh`는 측정 대상 태그의 바이너리 하나만 `$PATH`에서 해석된다.
- 응용 방화벽이 안에서 먼저 보낸 흐름의 답을 막으면 펀칭이 안 된다(ADR-0054 남는 위험). 장비 방화벽 설정(macOS "모두 차단", Windows 방화벽 정책)을 기록한다.
- 시도마다 `-v`(또는 `QSH_LOG=qsh::punch=info`)로 stderr를 파일에 뺀다. 이 줄이 `attempt`, `signaled`, `adopted`, `gave_up`의 정본이다(`docs/CLI.md` §7). IP와 포트는 줄에 없으므로 망의 주소는 기록하지 않아도 된다.

## 3. 망 쌍

A와 B에 아래 네 망을 돌려 가며 놓는다. 한 쌍은 A의 망과 B의 망 조합이다. 같은 종류의 망 두 곳(예: 휴대폰 둘)이면 다른 통신사로 놓는다.

| 망 | 설명 |
|---|---|
| 테더링 CGNAT | 휴대폰 테더링. 통신사 CGNAT 뒤. 통신사와 IPv4/IPv6 제공 여부를 적는다. |
| 집 공유기 | 가정용 공유기 뒤. 제조사와 모델, 펌웨어를 적는다. |
| 회사 망 | 회사 방화벽·프록시 정책 아래의 유선·무선. UDP가 나가는지 먼저 확인한다. |
| IPv6 전용 | IPv4 주소가 없는 망(NAT64/DNS64 포함). |

반드시 돌리는 쌍은 이렇다.

| 쌍 | A | B |
|---|---|---|
| 1 | 테더링 CGNAT | 집 공유기 |
| 2 | 집 공유기 | 테더링 CGNAT |
| 3 | 회사 망 | 집 공유기 |
| 4 | 테더링 CGNAT | 회사 망 |
| 5 | 테더링 CGNAT | 테더링 CGNAT (다른 통신사) |
| 6 | IPv6 전용 | 집 공유기 (IPv6 있음) |
| 7 | IPv6 전용 | IPv6 전용 |

R은 모든 쌍에서 A와 B가 모두 닿는 곳에 둔다. 쌍 6의 R은 IPv6로도 닿아야 한다. ADR-0054에 따라 후보는 family마다 하나씩만 reflexive를 얻으므로, A가 R에 IPv6로 닿고 B가 IPv4로 등록했다면 IPv4 쌍은 host 후보에 기대고 대개 실패한다. 이런 경우는 비고에 적는다.

## 4. 시도 한 번의 절차

쌍마다 같은 시도를 5번 반복한다. 반복 횟수 5는 §6의 중앙값과 최댓값이 의미를 갖는 최소값으로 이 문서가 고정한 값이다. 시도마다 새 프로세스로 시작하고, 이전 시도의 매핑이 남지 않도록 시도 사이에 30초 이상 쉰다(netsim의 매핑 수명 기본값이 30초다).

```bash
# A에서. B는 이름이 B인 pin이다.
qsh -v exec B -- true 2> attempt-N.log
echo $?
```

`qsh exec`가 끝나면 펀칭으로 선 연결 위에서 명령이 돈 것이다. 직접 dial이 먼저 서는 망이면 펀칭 줄 없이 끝날 수 있으므로, 그 경우는 직접 경로가 있는 쌍이라 제외하고 비고에 적는다.

실패한 시도의 사유는 같은 명령을 `--json`으로 돌려 `details.punch.reason`을 읽는다(`docs/CLI.md` §6.1).

```bash
qsh --json -v exec B -- true 2> attempt-N.log
```

기록하는 값은 다음과 같다.

- 종료 코드와 `exec` 성공 여부.
- stderr의 `adopted` 줄: `kind`, `family`, `elapsed_ms`, `losers_closed`, `tag_rejected`.
- 실패하면 `gave_up` 줄의 `reason`과 `elapsed_ms`, 그리고 `--json`의 `details.punch.reason`.
- 시도의 시작부터 `exec` 종료까지 걸린 벽시계 시간.
- 같은 쌍에서 `qsh doctor B --json`을 한 번 돌린 `data.punch`의 `outcome`.

## 5. 측정과 관측

- 펀칭이 열렸을 때 채택까지의 시간은 `adopted.elapsed_ms`다. 가상 망의 수치(netsim에서 신호 포함 route 시작부터 채택까지 p95 약 400 ms, 링크마다 한쪽 25 ms, `docs/adr/0054-m24-hole-punching.md` 개정 이력)와 비교하되 판정에 쓰지 않는다. 실제 망의 지연이 다르기 때문이다.
- 포기한 시도는 `gave_up.elapsed_ms`와 `reason`을 본다. 신호 3초와 창 5초를 합친 8초가 상한이고, 명령의 dial 시한 10초를 늘리지 않는다(`docs/CLI.md` §6.1).
- 열린 쌍은 연결이 선 뒤 A의 망을 한 번 바꿔 보고(Wi-Fi에서 테더링으로) 세션이 어떻게 되는지도 한 번 적는다. 펀칭한 경로는 A의 주소가 바뀌면 migration이 대개 실패하고 다시 펀칭해야 한다(ADR-0054 결정 18). 이 칸은 판정이 아니라 관찰이다.

## 6. 판정 기준 (실행 전에 고정, 사후 조정 없음)

| # | 판정 | 기준 |
|---|---|---|
| 1 | 열린 쌍의 속도 | 쌍의 5번 시도에서 열린 시도의 `adopted.elapsed_ms`가 모두 5초(채택 상한) 이하다. 신호 구간은 이 값에 들어가지 않는다 |
| 2 | 닫힌 쌍의 종결 | 열리지 않은 시도가 모두 8초 이내에 `gave_up`으로 끝나고 `reason`이 닫힌 어휘(`docs/CLI.md` §6.1) 가운데 하나다. 연결이 남거나 8초를 넘기는 시도가 하나도 없다 |
| 3 | 사유의 일관 | 열리지 않은 시도의 `--json` `details.punch.reason`이 stderr의 `gave_up.reason`과 같다 |
| 4 | 정보 노출 없음 | 모든 `qsh::punch` 줄과 `details`에 IP 주소나 포트가 없다 |
| 5 | 기대 쌍 | 양쪽이 symmetric이거나 한쪽이 symmetric이고 다른 쪽이 port-restricted임이 확인된 쌍은 `timeout`으로 끝나는 것이 기대 동작이다. 이 쌍이 열리면 이상이 아니라 기록으로 남긴다 |

판정 1과 2는 쌍마다 따로 본다. 판정 1에서 5번 중 열린 횟수는 PASS 기준이 아니다. 어떤 망 쌍이 열리느냐가 이 캠페인이 알려 주려는 결과이므로, 열린 횟수는 §7 표에 적고 합격 선을 두지 않는다. 쌍 PASS는 판정 1~4를 모두 만족하는 것이다. 캠페인 PASS는 돈 쌍이 모두 PASS인 것이다.

## 8. FAIL의 처분

이 캠페인은 마일스톤을 막지 않는다. 실패한 쌍은 원인을 비고에 원문으로 남기고 별도 이슈로 올린다. 판정 기준은 고치지 않는다. 기준이 틀렸다고 판단되면 ADR-0054를 고치는 새 ADR을 제안하고 그 승인 뒤에 이 문서를 고쳐 새 회차를 돈다.

열리지 않은 쌍이 NAT 모델로 설명되면(symmetric 쌍 등) 결함이 아니라 ADR-0054가 남긴 위험의 실측이다. 그 NAT 종류와 모델을 비고에 적고, 열리리라 기대한 쌍이 열리지 않은 경우만 netsim의 NAT 상자 표나 `scripts/netns/punch.sh`에 그 동작을 재현하는 행을 더하는 후속 이슈로 올린다.
