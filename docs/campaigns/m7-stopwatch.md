# M7 SC1 스톱워치 캠페인 — README만 보고 5분 내 접속

상태: 기준 확정, 공식 캠페인 미실행. 예행(dry run) 1회를 수행해 이 문서의 프로토콜 자체를 검증했다(§9) — 예행은 이 캠페인이 아니다. 3회 공식 측정은 이 문서의 기준이 커밋된 뒤 별도로 수행하고, 그 결과를 §8에 채운다.

## 1. 목적과 지위

`docs/PRD.md` §15가 성공 기준 1번과 2번으로 각각 이렇게 적는다.

> 신규 두 장비의 최초 연결을 5분 이내에 완료한다.
> 등록된 host에는 한 개의 명령으로 접속한다.

`docs/ROADMAP.md` M7의 DoD 1은 이걸 실행 가능한 절차로 옮긴다.

> 스톱워치 테스트 — 한 번도 설정한 적 없는 두 장비가 README만 보고 `qsh user@host`까지 5분 이내, 독립 3회 측정·기록 (SC1, SC2)

`PLAN.md` Step 8 (a)는 실행 조건을 더 좁힌다: "한 번도 설정한 적 없는 두 장비(신선한 sandbox 프로필 2식 또는 실장비 2대), README만 보고 `qsh user@host`까지, 독립 3회, 5분 기준." (d)는 완료 판정을 "캠페인 3회 기록 완료(전건 5분 이내)"로 못박는다.

이 캠페인은 M2 mobility 캠페인과 다르다. M2는 참고 자료였고 실패 회차가 마일스톤을 막지 않았다. 이 캠페인은 M6 MCP 캠페인과 같은 자리에 있다 — **DoD 1 그 자체이며 합격/불합격 게이트다.** 3회 전부가 5분 이내여야 M7을 닫을 수 있다.

## 2. 대상 문서

`README.md`의 "First run" 절 하나만 — "Quick start" 절도, "Security posture" 절도 아니다. 피실험자에게는 이 절 외에 아무것도 열어주지 않는다.

측정 종점은 그 절 안에서도 이르게 온다. "First run" 절은 `qsh dave@box`로 첫 셸을 얻은 뒤에도 pairing과 `hosts.toml` 이야기를 계속하지만, 스톱워치는 첫 셸에서 멈춘다 — 그 뒤 문단은 피실험자가 읽을 필요도, 캠페인이 측정할 이유도 없다.

## 3. 전제 조건 — "한 번도 설정한 적 없다"의 조작적 정의

두 장비 각각에서 아래가 전부 사실이어야 타이머를 시작할 자격이 있다.

- `$XDG_CONFIG_HOME/qsh`(보통 `~/.config/qsh`)가 없다 — `identity.toml`, `trust.toml`, `acl.toml`, `hosts.toml`, `config.toml` 전부 부재.
- `$XDG_STATE_HOME/qsh`(보통 `~/.local/state/qsh`)가 없다 — `resume.json`, `audit.log` 부재.
- OS 자격 증명 저장소(macOS Keychain, Linux Secret Service)에 `service=qsh` 항목이 없다.
- `$PATH`상에 다른 `qsh` 실행 파일이 없다 — 테스트 대상 바이너리 하나만 해석된다.
- README가 예시로 쓰는 포트(`4433`)를 선점한 프로세스가 없다.
- 잔존 `qsh serve` / `qsh reverse` / `qsh listen` 프로세스가 없다.

이걸 매번 손으로 보장하는 가장 확실한 방법은 회차마다 새로 만들고 끝나면 버리는 **두 개의 VM 또는 컨테이너**를 쓰는 것: `$HOME`이 비어 있으면 위 조건이 전부 자동으로 성립하고, 피실험자는 README에 없는 환경 변수(`QSH_CONFIG_DIR` 등)를 몰라도 된다. README의 "First run" 절 자체가 그런 변수를 요구하지 않으니, 피실험자가 타이핑하는 명령은 README에 적힌 것 그대로여야 한다. 실장비 2대를 쓸 경우 위 6개 항목을 회차 시작 전 손으로 지우고 확인한다.

두 장비는 서로 실제 네트워크 경로로 도달 가능해야 한다 — 같은 머신의 loopback으로 대신하면 "두 장비"라는 전제 자체가 무너진다. 같은 LAN이나 브리지 네트워크의 VM 두 대면 충분하다.

### 진행자용 사전 점검 체크리스트 (타이머 밖, 진행자가 수행)

피실험자가 아니라 **진행자**가 타이머 시작 전에 아래를 확인한다. 확인 자체는 qsh 명령을 쓰지 않는다 — qsh 명령을 미리 실행해 보면 그게 곧 연습이 되어 버린다.

1. 두 장비 모두 §3의 6개 조건 확인.
2. `which -a qsh` (Windows는 `where qsh`)로 PATH 그림자 없음 확인. 이 시점엔 아직 `qsh init`을 안 해서 `qsh doctor`를 쓸 수 없다 — identity가 없으면 `doctor.run`은 조회 자체를 시작하지 못하고 exit 255로 실패한다(`docs/CLI.md` §6.17).
3. `lsof -i :4433` 또는 동등 명령으로 대상 포트에 남은 프로세스 없음 확인.
4. `ps aux | grep qsh` 로 잔존 `qsh serve`/`reverse`/`listen` 없음 확인.
5. 두 장비 사이 물리적 네트워크 경로가 살아 있음을 ping 등 qsh 아닌 도구로 확인(선택 — 이미 알고 있으면 생략 가능).
6. 스톱워치와 기록 표(§6) 준비.
7. 피실험자에게 README "First run" 절만 열어준다. 다른 절은 닫아 두거나 접근을 막는다.

이 예행에서 실제로 걸렸던 것 두 가지가 여기 항목 2, 3, 4다 — 이 개발 머신에 이 예행과 무관한 leftover `qsh serve`가 포트를 선점했고, PATH 앞쪽에 구버전 `qsh`가 그림자로 있었다(§9).

## 4. 두 터미널의 배치 — 한 사람, 화면 분할로 고정

지문을 옮기고 대조하는 구간이 README도 자인하는 최대 병목이라, 두 터미널을 어떻게 보는지가 회차마다 다르면 측정치가 재현되지 않는다. 이 캠페인은 하나로 고정한다.

**한 사람이 한 화면에 두 터미널을 나란히 띄워 놓고(탭 분할이든 창 두 개든) 스스로 오간다.** 음성이나 채팅으로 지문을 불러주는 두 사람 릴레이 방식은 쓰지 않는다.

이유는 단순하다. 두 사람 릴레이는 qsh의 UX가 아니라 두 사람 사이의 통신 지연을 재는 셈이 된다. SC1이 재려는 건 "이 소프트웨어가 얼마나 빨리 붙는가"지 "전화로 숫자를 불러주는 데 얼마나 걸리는가"가 아니다. 분산된 두 사람이 실제로 페어링하는 시나리오의 체감 시간이 궁금하다면 그건 이 캠페인과 별개로 측정할 문제이며, 지금 SC1 숫자에 섞지 않는다.

## 5. 사전 정의된 합격/불합격 기준 (실행 전에 고정, 사후 조정 없음)

| 항목 | 정의 |
|---|---|
| 타이머 시작 | 피실험자가 README "First run" 절의 첫 명령(호스트 쪽 `qsh init --json`)에 첫 키를 입력하는 순간 |
| 타이머 종료 | 클라이언트 쪽 `qsh dave@box`(또는 그에 대응하는, README 그대로 따른 이름)를 실행한 뒤 원격 셸 프롬프트가 화면에 처음 나타나는 순간 |
| 예산 | 300초(5분), 회차당 |
| 회차 PASS | 시작~종료가 300초 이내이고, 피실험자가 README "First run" 절에 적힌 명령·순서를 그대로 따랐다(진행자 개입 없음) |
| 회차 FAIL | 300초 초과, 또는 피실험자가 막혀서 README 문면만으로 종점에 도달하지 못함(진행자가 힌트를 주면 그 시점부터 FAIL 확정) |

"독립 3회"는 **환경의 독립**을 뜻한다 — 회차마다 §3의 여섯 조건을 처음부터 다시 충족한 상태에서 시작한다(설정·자격 증명·프로세스·포트 전부 새로). 사람의 독립까지는 요구하지 않는다: 같은 조작자가 3회를 연달아 수행해도 캠페인 자체는 유효하다. 다만 같은 사람이 반복하면 두 번째, 세 번째 회차는 타이핑 속도와 절차 암기로 빨라지는 게 당연하므로, 1회차를 진짜 최초 노출로 삼는 걸 원칙으로 하고, 2·3회차에 학습효과가 있었다면 §6 기록표 비고란에 그렇게 적는다 — 학습효과를 감추고 평균만 내지 않는다. 가능하다면 qsh를 접해본 적 없는 별도 인원이 1회차를 맡는 편이 SC1의 취지에 더 가깝지만, 그게 항상 가능한 건 아니므로 이 문서는 그것을 강제 조건이 아니라 권고로만 남긴다.

## 6. 측정 프로토콜과 기록 템플릿

## 7. 실패 시 처분

300초를 넘긴 회차가 나오면 먼저 원인을 분류한다.

- **README 문면의 결함** (피실험자가 문면을 정확히 따랐는데도 막혔다 — 예: 이번 예행이 잡은 것처럼 절 사이에 필요한 단계가 빠져 있거나 순서가 틀렸다) → README를 고치고, 그 시점부터 3회 카운트를 처음부터 다시 시작한다. 고치기 전 회차와 고친 후 회차는 서로 다른 문면을 측정한 것이라 같은 캠페인으로 묶을 수 없다.
- **제품 결함** (문면대로 했는데 qsh 자체가 기대와 다르게 동작했다) → 이슈로 승격하고 M7 백로그 또는 즉시 수정 대상으로 분류한다. README를 손대는 문제가 아니므로 문면 수정 없이 제품을 고친 뒤 재측정한다.
- **환경/진행자 잡음** (§3 사전 점검을 놓쳐 leftover 프로세스나 포트 충돌 같은 게 섞였다) → 그 회차는 PASS도 FAIL도 아닌 **무효**로 기록하고 카운트에서 뺀다. 사전 점검을 다시 하고 새 회차로 대체한다.

사후에 5분 기준 자체를 늘리거나, 실패한 회차를 조용히 빼고 성공한 회차만 보고하는 건 하지 않는다 — §5의 기준은 처음 커밋된 그대로 남는다.

## 9. 예행(dry run) 요약 — 2026-09-01, 이 캠페인이 아니다

공식 3회 측정에 앞서 이 문서의 프로토콜 자체가 말이 되는지 확인하려고 예행 1회를 돌렸다(`ROADMAP.md` §4 리스크 3의 "조기·반복" 대응, `PLAN.md` Step 8 (a)). 예행은 §5의 pass/fail 판정 대상이 아니다 — 회차로 세지 않는다.

**기계가 쓰는 시간은 총 0.65~0.72초, 5분 예산의 0.25% 미만이다.** README "First run" 절의 문자 그대로의 스크립트(6개 명령 + acl.toml 1개)는 기계적으로는 전혀 병목이 아니다. 300초 예산은 사실상 전부 사람 시간 — 문서 읽기, acl.toml 손으로 쓰기, fingerprint 옮겨 적고 대조하기, 터미널 오가기 — 이고, 딱 하나의 막힌 지점이 예산 전체를 날릴 수 있다.

예행이 잡은 것:

- README "Quick start" 절은 acl.toml을 한 번도 언급하지 않고 바로 `qsh exec box -- uname -a`로 넘어가, 그 절만 보고 따라 하면 첫 명령이 100% `PERMISSION_DENIED`로 막혔다. 이번 캠페인이 "Quick start"가 아니라 "First run" 절만 대상으로 삼는 이유이자, §2에서 대상 절을 좁혀 못박은 이유다.
- 기본 플래그 없는 `qsh init --json`이 아무 안내 없이 macOS 실 Keychain(또는 Linux Secret Service)에 항목을 실제로 쓴다. 문면이 요구하는 그대로의 명령이라 캠페인에서 피할 수 없고, §3이 회차마다 새 VM/컨테이너를 쓰도록 못박은 이유 중 하나다 — 그래야 이 부작용도 회차 간에 오염되지 않고, 끝나면 컨테이너와 함께 버려진다.
- 이 개발 머신에 이 예행과 무관한 leftover `qsh serve` 프로세스가 포트를 선점해 첫 시도가 실패했고, PATH 앞쪽에 구버전 `qsh`가 그림자로 있었다. 둘 다 §3 사전 점검 체크리스트에 항목으로 반영했다.
- fingerprint 손타이핑·대조는 예행에서 스크립트가 JSON을 파싱해 대신 채웠기 때문에 사람 시간이 0으로 잡혔다 — 실측이 아니라 과소측정이다. 공식 캠페인은 사람이 직접 옮기고 대조해야 진짜 숫자가 나온다.

예행 실측 표(6단계, echo 왕복 확인까지 포함한 기계 시간):

| 단계 | 명령 | 기계 소요(초) |
|---|---|---|
| host init | `qsh init --json --key-store file` | 0.055 |
| host serve | `qsh serve --bind …` | 0.051 |
| client init | `qsh init --json --key-store file` | 0.051 |
| client trust add | `qsh trust add box --address … --fingerprint …` | 0.035 |
| host trust add | `qsh trust add laptop --fingerprint …` | 0.024 |
| client 첫 셸 | `qsh dave@box`(첫 바이트/echo 왕복) | 0.436 / 0.505 |

합계 ≈ 0.65~0.72초. 예행은 `--key-store file`을 강제해 Keychain 오염을 피했지만(§3이 이미 지적했듯 공식 캠페인은 문면 그대로 플래그 없이 실행해야 한다), 그 점을 빼면 명령 순서와 내용은 README "First run" 절과 동일했다.
