# P1 `qsh setup` 스톱워치 — 안내만 따라 5분 내 접속

상태: 기준 확정, 예행·공식 캠페인 미실행.

## 1. 목적과 지위

이슈 #3의 완료 기준 첫 줄은 대상 문서 없이 두 장비를 5분 안에 잇는 것이다. ADR-0024 결정 12는 `qsh setup`의 효과를 이 캠페인이 사후에 판정한다고 정했다. 설계가 먼저 착지했고 측정은 그 뒤에 온다.

`docs/campaigns/m9-stopwatch.md`는 README "First run" 절이라는 수동 경로를 잰다. 이 캠페인은 같은 두 장비, 같은 종점에서 `qsh setup`의 프롬프트와 인쇄 출력만 따르는 경로를 잰다. 형식은 `m9-stopwatch.md` §3~§8을 계승한다.

`m9-stopwatch.md`와 마찬가지로 합격/불합격 게이트다. PASS가 기록되기 전에는 `qsh setup`이 이슈 #3 완료 기준 첫 줄을 충족했다고 적지 않는다. 이 캠페인은 사람 몫이므로 자동 테스트로 대신하지 않는다.

`m9-stopwatch.md`의 대상 트리와 §5 기준은 이 문서가 바꾸지 않는다.

## 2. 대상 문서 없음, 피실험자 지시 한 줄

이 캠페인에는 대상 문서가 없다. README도, `docs/CLI.md`도 열어주지 않는다. 피실험자는 §3 조건의 두 장비와 아래 지시 한 줄만 받는다.

> 두 장비에서 `qsh setup`을 실행하고 그 안내만 따른다.

이후 피실험자가 따르는 것은 `qsh setup`의 프롬프트, 인쇄된 `[[acl]]` 행, `next` 목록뿐이다. 진행자는 어떤 명령이나 플래그도 알려주지 않는다. 상대 장비에서 칠 `qsh setup client …`는 host 쪽 `next`가 인쇄한다.

## 3. 전제 조건 — "한 번도 설정한 적 없다"의 조작적 정의

`m9-stopwatch.md` §3의 일곱 조건을 두 장비 각각에 그대로 적용한다.

- `$XDG_CONFIG_HOME/qsh`(보통 `~/.config/qsh`)가 없다. `identity.toml`, `trust.toml`, `invites.toml`, `acl.toml`, `hosts.toml`, `config.toml` 전부 부재.
- `$XDG_STATE_HOME/qsh`(보통 `~/.local/state/qsh`)가 없다. `resume.json`, `audit.log` 부재.
- OS 자격 증명 저장소(macOS Keychain, Linux Secret Service)에 `service=qsh` 항목이 없다.
- `$PATH`상에 다른 `qsh` 실행 파일이 없다.
- 포트 `4433`을 선점한 프로세스가 없다.
- 잔존 `qsh serve` / `qsh serve --to` / `qsh listen` 프로세스가 없다.
- `qsh service status`가 "미등록"이다(`installed: false`, `docs/CLI.md` §6.18).

회차마다 새로 만들고 버리는 VM 또는 컨테이너 두 개를 쓰면 이 조건이 자동으로 성립한다. `scripts/stopwatch/round.sh N`을 그대로 재사용한다. 두 장비는 loopback이 아닌 실제 네트워크 경로로 도달 가능해야 한다.

진행자용 사전 점검(타이머 밖)은 `m9-stopwatch.md` §3의 체크리스트 1~7을 따른다. 8번(README 열어주기)만 바꿔서, 피실험자에게 아무 문서도 열어주지 않고 지시 한 줄만 준다. 점검에 qsh 명령을 쓰지 않는다. 미리 실행하면 연습이 된다.

## 4. 두 터미널의 배치

`m9-stopwatch.md` §4와 같다. 한 사람이 한 화면에 두 터미널을 나란히 띄우고 스스로 오간다. 두 사람 릴레이는 쓰지 않는다. 초대 코드를 옮기는 구간은 복사·붙여 넣기든 눈으로 옮겨 치기든 피실험자가 고른 방식대로 두고, 고른 방식을 §6 비고란에 적는다.

## 5. 사전 정의된 합격/불합격 기준 (실행 전에 고정, 사후 조정 없음)

| 항목 | 정의 |
|---|---|
| 타이머 시작 | 피실험자가 지시 한 줄을 받은 뒤 host 쪽에서 `qsh setup`의 첫 글자를 입력하는 순간 |
| 타이머 종료 | client 쪽에서 첫 원격 셸 프롬프트가 화면에 처음 나타나는 순간 |
| 예산 | 300초(5분), 회차당 |
| 회차 PASS | 시작~종료가 300초 이내이고, 피실험자가 `qsh setup`의 프롬프트·인쇄 행·`next`만 따랐다(진행자 개입 없음) |
| 회차 FAIL | 300초 초과, 또는 피실험자가 막혀서 setup 출력만으로 종점에 도달하지 못함(진행자가 힌트를 주면 그 시점부터 FAIL 확정) |
| 캠페인 PASS | 독립 3회 전부 300초 이내이고, 3회의 중앙값이 비교 세트 m9 3회의 중앙값보다 짧다 |
| 캠페인 FAIL | 3회 중 하나라도 300초를 넘기거나, 중앙값이 비교 세트 중앙값 이상이다. §7의 처분을 따른다 |
| 비교 세트 | 같은 진행자가 같은 날 잰 m9 3회다. M9 DoD 1 공식 회차가 그날이면 그 세트를 쓰고, 아니면 그날 `m9-stopwatch.md` §8의 고정 트리로 m9 3회를 따로 잰다 |

"독립 3회"는 환경의 독립이다. 회차마다 §3의 일곱 조건을 처음부터 다시 충족한다. 같은 조작자가 연달아 수행해도 유효하지만, 2·3회차에 학습효과가 있었다면 §6 비고란에 적는다. 학습효과를 감추고 중앙값만 내지 않는다.

## 6. 측정 프로토콜과 기록 템플릿

피실험자가 치는 명령을 이 문서가 정하지 않는다. 아래 표는 기대하는 흐름이고 실제 순서와 다르면 다른 대로 적는다. `qsh setup`은 `acl.toml`을 쓰지 않으므로(ADR-0024 결정 3) 2행의 붙여 넣기는 사람 구간으로 남는다. 초대는 `qsh serve` 기동 전에 발급되지만 상환은 serve가 떠 있어야 하므로 serve 기동이 client 단계보다 앞선다.

| # | 단계 | 담당 | 유형 | 비고 |
|---|---|---|---|---|
| 1 | `qsh setup` 실행, 역할·pin 이름 프롬프트 응답 | host | 기계+사람 | 타이핑과 프롬프트 읽기는 사람 구간으로 쪼갠다 |
| 2 | 인쇄된 `[[acl]]` 행을 `acl.toml`에 붙여 넣고 저장 | host | 사람 | |
| 3 | 저장 확인(Enter)과 `acl.check` 검증, 초대 코드 발급 | host | 기계 | |
| 4 | 초대 코드와 `next`의 client 명령 옮기기 | host→client | 사람 | §4대로 한 화면에서 |
| 5 | `qsh serve` 기동 | host | 사람+기계 | 명령 타이핑은 사람, 기동은 기계 |
| 6 | `qsh setup client …` 입력과 실행 | client | 사람+기계 | 상환·pin·doctor는 기계 구간 |
| 7 | 첫 셸 명령 입력과 접속 | client | 사람+기계 | 원격 프롬프트 첫 출력까지, 타이머 종료 |

## 7. 실패 시 처분

300초를 넘긴 회차나 중앙값 미달이 나오면 먼저 원인을 분류한다.

- **`qsh setup` 출력의 결함** (프롬프트·인쇄 행·`next`를 정확히 따랐는데도 막혔다) → 출력 문면을 고치고 그 시점부터 3회 카운트를 처음부터 다시 시작한다. 고치기 전과 후는 다른 문면을 측정한 것이라 같은 캠페인으로 묶을 수 없다.
- **제품 결함** (안내대로 했는데 qsh 자체가 기대와 다르게 동작했다) → 이슈로 승격하고 고친 뒤 재측정한다.
- **환경/진행자 잡음** (§3 사전 점검을 놓쳐 잔존 프로세스·포트 충돌·서비스 유닛이 섞였다) → 그 회차는 PASS도 FAIL도 아닌 무효로 기록하고 카운트에서 뺀다. 사전 점검을 다시 하고 새 회차로 대체한다.

원인이 어느 쪽이든 자동 신뢰는 처분 후보가 아니다. 미지 peer를 자동으로 pin해서(TOFU) 5분을 맞추지 않는다. `trust.toml`의 pin은 방향을 가리지 않아서 client 쪽 자동 pin이 같은 상대의 inbound 인증까지 열어 주기 때문이다(ADR-0017 결정 5). `qsh setup`이 pin하는 근거는 초대 코드와 인증서 파일 둘뿐이고(ADR-0024), 이 캠페인은 그 둘만 허용한다. 관측한 fingerprint를 y/n으로 pin하는 경로를 추가해 시간을 줄이는 것도 처분 후보가 아니다.

사후에 5분 기준을 늘리거나, 실패한 회차를 조용히 빼고 성공한 회차만 보고하거나, 비교 세트를 다른 날이나 다른 진행자의 것으로 바꾸는 일은 하지 않는다. §5의 기준은 처음 커밋된 그대로 남는다.

## 8. 환경 기록과 실행 기록 (공식 캠페인 수행 시 채운다)

같은 진행자가 같은 날 안에 비교 세트 m9 3회와 이 캠페인의 3회를 이어서 수행한다. 서로 다른 날이나 다른 진행자가 재면 중앙값 차이가 표면의 차이인지 사람·환경의 차이인지 구분할 수 없다.

|---|---|---|
| 날짜(UTC) | | |
| 진행자 | | (비교 세트와 동일해야 함) |
| host 장비/OS | | |

회차 1, 2, 3의 §6 기록표와 요약을 각 세트마다 여기 또는 이 절 아래에 이어 붙인다. 이 캠페인 3회 전부 300초 이내이고 중앙값이 비교 세트 중앙값보다 짧으면 캠페인 PASS로 결론짓고, 그 기록을 근거로 이슈 #3 완료 기준 첫 줄의 충족을 적는다.
