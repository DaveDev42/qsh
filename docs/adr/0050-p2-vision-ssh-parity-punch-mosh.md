# ADR-0050: P2의 목표를 "SSH 주요 기능 + 홀펀칭 + mosh 수준 사용성"으로 정하고, 설정 없이 대화형으로 쓰며 SSH 명령과 호환하는 것을 원칙으로 둔다

날짜: 2026-11-05
상태: 승인됨 (2026-11-05, 사용자 결정 "좋아. 충분히 고민해봐.")

개정 관계: `docs/PRD.md` §4 "Direct first" 문단, §4에 새 원칙 하나, §7 P2 목록, §12 "QSH 밖에서 해결하는 것"의 NAT traversal 항목을 바꾼다. §3 목표 8("relay 없이 완전히 동작한다")과 relay를 별도 제품으로 두는 §14는 그대로다. `docs/ROADMAP.md` 머리의 "P2는 다루지 않는다"를 바꾸고 §6 P2 마일스톤을 연다. 2026-10-12 사용자 결정으로 기각된 listener 초대 코드 pairing(ADR-0015)은 다시 열지 않는다.

## 맥락

P0(M0~M10)와 P1(M11~M20)의 기능은 모두 착지했다. 남은 것은 사람이 돌리는 회차와 조건부 M18이다. qsh는 IP 변경·sleep을 넘는 세션 유지, 연결과 분리된 세션 수명과 재부착, `-L`/`-R`/`-D` 터널, scp 호환 `qsh cp`, 역방향 접속, 역할 기반 권한, 감사 기록, `qsh.cli/v1` JSON 계약을 갖는다. SSH에는 로밍과 재부착이 없고, mosh에는 포워딩·재부착·파일 복사가 없다.

2026-11-05 사용자가 다음을 정했다.

- 목표: "SSH의 상용 기능 대부분 + 홀펀칭 + mosh 수준의 사용성."
- 홀펀칭: "맨 처음에 펀칭만 하는 것이고, 홀펀칭으로 접근이 안 되면 포기한다."
- 불만: "설정 파일에 의존하는 게 너무 많아서 CLI 사용 편의성이 별로다."
- 원칙: "설정 파일에 크게 의존하지 않고, 쉽게, interactive하게 쓰면서도, SSH 명령어들과 하위 호환성을 유지한다."

같은 날 조사한 마찰 목록(이 ADR의 근거, 아래 결정 5의 표)은 설정 파일 손편집이 남은 곳을 이렇게 짚었다. 역방향 상시 서비스의 `[serve].to`·`[listen]`, 원격 PATH 밖 qsh의 `[ssh].remote_qsh`, 역할보다 세밀한 권한과 모든 파일 경로 허용의 `acl.toml`(재시작 필요), 상시 기동의 OS별 수작업(linger, LaunchDaemon, 관리자 `schtasks`), 기본으로 켜지지 않는 `service install`. mosh는 `ssh host`로 들어간 김에 `mosh-server`를 그 자리에서 띄우므로 서버 쪽에 데몬도, 서비스 등록도, 신뢰 설정도 없다.

지금의 PRD와 부딪히는 곳은 §4와 §12의 "NAT traversal은 코어 밖"이다. 로컬 에코 예측, jump chaining, agent forwarding은 이미 §7 P2 목록에 있다.

## 결정

1. P2를 연다. 목표 문장은 "SSH의 주요 기능 대부분, 연결 시작 때 한 번의 홀펀칭, mosh 수준의 사용성"이다.

2. P2의 모든 마일스톤은 다음 세 원칙을 수용 기준으로 진다.
   - **설정 파일 없이 동작이 기본이다.** 흔한 경로(첫 접속, 셸, exec, 터널, 파일 복사, 상시 serve, 역방향)는 설정 파일을 손으로 열지 않고 끝난다. 설정 파일은 qsh가 쓰는 저장소이고, 사람이 고칠 수는 있지만 고쳐야 하는 곳이 아니다. 새 설정 키를 더할 때는 같은 값을 정하는 CLI 경로(플래그나 명령)를 함께 둔다.
   - **대화형이 기본이고, 스크립트는 같은 일을 플래그로 한다.** TTY에서는 qsh가 빠진 것을 물어보고(원격에 qsh가 없을 때 설치할지, 처음 보는 상대를 믿을지, 어떤 역할을 줄지), 답을 저장해 다음에는 묻지 않는다. 묻는 것마다 같은 답을 주는 플래그가 있고, `--json`/`--jsonl`이나 TTY가 아닐 때는 묻지 않고 플래그가 없으면 실패한다. 묻는 글은 stderr로 가므로 기계 모드의 stdout 순수성은 그대로다.
   - **SSH 명령과 하위 호환한다.** `alias ssh=qsh`를 걸어도 흔한 `ssh` 쓰임새가 같은 뜻으로 동작한다. 대상은 `ssh [user@]host [command...]`의 문법과 argv 의미, 흔한 옵션(`-l`, `-p`, `-L`, `-R`, `-D`, `-J`, `-A`, `-t`, `-T`, `-N`, `-f`, `-i`, `-o`, `-F`, `-v`, `-q`, `-4`, `-6`), 원격 exit code를 그대로 돌려주고 qsh 자신의 오류는 255로 끝내는 종료 상태, `~.` 같은 escape, `~/.ssh/config`의 `Host` 별칭과 `HostName`·`User`·`Port`·`ProxyJump`다. `qsh cp`의 scp 호환(ADR-0029)도 같은 원칙에 든다. 뜻이 없는 옵션(예: `-X`)은 조용히 무시하지 않고 그 이름을 대며 거부한다. qsh에서 같은 글자가 다른 뜻이던 곳은 SSH 쪽 뜻으로 맞추고, 바뀌는 qsh 옛 표기는 v1 동안 숨김 alias로 남긴다(ADR-0019·ROADMAP M9 Q2의 선례).

3. NAT traversal 가운데 **홀펀칭만** 코어에 들어온다. 둘 다 닿는 사용자의 qsh peer 하나를 중개자로 써서 연결을 시작할 때 구멍을 뚫는다. 실패하면 거기서 끝내고 이유를 담은 오류를 낸다. relay, TURN, 공용 STUN 서버, 중앙 서비스는 들이지 않는다. 설계는 M24의 ADR이 정한다.

4. PRD 문장을 이렇게 바꾼다.
   - §4 "Direct first": "두 endpoint 사이에 IP 경로가 있거나, 둘 다 닿는 사용자의 qsh peer를 중개자로 써서 홀펀칭으로 경로를 열 수 있으면 제3자 서비스 없이 작동한다. 홀펀칭은 연결을 시작할 때 한 번 시도하고 실패하면 포기한다. relay는 코어에 포함하지 않는다(§14)."
   - §4에 "Configuration-free, interactive, SSH-compatible" 원칙을 더한다. 내용은 결정 2의 세 항목이다.
   - §7 P2 목록을 결정 5의 마일스톤으로 바꾸고, read-only multi-attach는 P2 후보로 남긴다.
   - §12 "QSH 밖에서 해결하는 것"의 "NAT traversal"을 "홀펀칭으로 열리지 않는 NAT(양쪽 모두 목적지마다 매핑이 바뀌는 NAT 등)의 통과"로 바꾼다.

5. P2 마일스톤과 순서는 다음과 같다. 크기는 1인 기준 추정이고, 범위의 세부는 마일스톤마다 첫 스텝의 ADR이 정한다.

   | 마일스톤 | 범위 | 크기 |
   |---|---|---|
   | M21 설정 없는 첫 접속과 SSH 명령 호환 | mosh식 부트스트랩: `qsh host` 한 줄이 SSH로 한 번 들어가 원격 qsh를 찾거나 (동의를 받아) 설치하고, 사용자 권한의 serve를 필요할 때 띄워(세션이 있는 동안 살고 마지막 세션이 끝나면 내려간다) 양쪽 pin을 맞춘 뒤 QUIC으로 붙는다. `ssh` 문법·옵션·종료 상태·`~/.ssh/config` 호환(결정 2). 상시 serve는 `service install`이 기본으로 켜고 OS별 로그인 밖 기동을 한 명령으로 다루며, `--to`·`--bind`를 유닛에 기록한다. 역할보다 세밀한 권한을 CLI로 주고 다시 읽는 경로. 재페어링 때 pin 교체 | 4ew |
   | M22 화면 상태 동기화 | 대화형 form에서 host가 터미널 상태를 들고 client에는 현재 화면과의 차이만 보낸다. 재부착은 현재 화면 한 장으로 끝나고, 출력이 밀리면 중간 화면을 건너뛰어 입력(Ctrl-C)이 바로 닿는다. `--json`/`--jsonl`의 `session.output`·`session read`의 바이트 계약은 그대로다 | 4ew |
   | M23 로컬 에코 예측과 연결 상태 줄 | M22의 화면 모델 위의 mosh식 예측. 확인 전 글자는 밑줄로 그리고, echo-off 구간·전체 화면 앱·연속 오예측에서는 끈다. 응답이 끊기면 "마지막 응답 N초 전" 줄을 띄우고 입력은 받아 둔다 | 3ew |
   | M24 홀펀칭 | 결정 3. 중개자 경유 후보 교환, 동시 송신, 첫 handshake 채택, 실패 시 포기 | 3ew |
   | M25 agent forwarding | `-A`. 원격에서 로컬 ssh-agent(unix socket, Windows named pipe)를 쓰게 하는 스트림. 기본 꺼짐, 역할로 허용 | 2ew |
   | M26 jump chaining | `-J`와 `ProxyJump`. 중간 peer가 다음 peer로의 QUIC를 터널로 잇고, 끝단 인증은 끝단 pin으로 한다 | 2ew |

6. X11 forwarding은 P2에 넣지 않는다(`-X`/`-Y`는 이름을 대며 거부한다). sftp 하위 시스템 호환은 후보로만 남긴다.

7. P1의 시퀀싱 원칙(ROADMAP §5.1)을 P2에도 적용한다. 계약·wire를 건드리는 스텝은 그 ADR 승인 전에 열지 않는다. 정방향과 역방향, Linux·macOS·Windows는 같은 기능을 갖는다. 사람 회차는 DoD에 넣지 않는다. wire 변경은 발효된 freeze(`docs/design/protocol.md` §16.4)의 additive 규율을 따르고, JSON은 `qsh.cli/v1` additive 규율을 따른다.

## 근거

- 사용자가 목표와 원칙을 정했다.
- 로밍과 재부착은 이미 mosh 이상이다. mosh 사용성에서 비어 있는 것은 설치·설정이 없는 첫 접속, 화면 상태 동기화(재부착 즉시성, 느린 링크의 입력 응답), 지연을 가리는 예측 표시다. SSH 기능에서 자주 쓰이는데 비어 있는 것은 SSH 그대로의 명령 문법, agent forwarding, jump host다.
- M21을 맨 앞에 둔다. 사용자가 지금 겪는 불편이 가장 크고, SSH 호환 문법은 M25(`-A`)·M26(`-J`)이 그 위에 선다.
- M22를 M23 앞에 둔다. 예측 표시는 client 쪽 화면 모델을 전제로 한다.
- 화면 상태 동기화는 재생분에서 생기는 문제를 구조로 없앤다. ADR-0048이 막은 재생분 터미널 질의 누출과, 캠페인 W1에서 본 폭이 다른 터미널의 재그리기 찌꺼기(`docs/campaigns/p1-windows.md` §7 W1 관측 재확인)가 그것이다.
- 홀펀칭을 "연결 시작 때 한 번, 실패하면 포기"로 묶으면 relay 없이도 끝이 있는 범위가 된다. 중개자를 사용자의 qsh peer로 두면 PRD §1의 "중앙 서버나 relay 없이"를 지킨다.

## 대안과 기각 사유

- **relay를 함께 넣는다.** 실패를 줄이지만 PRD §14가 별도 제품으로 뺀 것이고, 사용자가 실패 시 포기를 택했다. 기각.
- **공용 STUN 서버로 바깥 주소를 얻는다.** 제3자 서비스 의존이 생긴다. 중개자가 같은 일을 한다. 기각.
- **listener 초대 코드 pairing을 되살려 역방향 설정을 줄인다.** 2026-10-12 사용자 결정으로 기각됐고(ADR-0015), 같은 목적을 SSH 부트스트랩이 채운다. M21은 역방향도 SSH 부트스트랩으로 다룬다. 기각.
- **SSH 호환을 별도 `qsh ssh` 하위 명령으로만 준다.** `alias ssh=qsh`가 되지 않는다. 기각.

## 결과

- 이 ADR을 담은 커밋에서 PRD §4·§7·§12를 결정 4대로 고치고, ROADMAP 머리 문장과 §6 P2 절(M21~M26)을 더한다.
- M21의 첫 스텝은 M21 범위를 정하는 ADR이다. 승인 전에는 계약·wire 스텝을 열지 않는다. PLAN.md는 그 ADR이 승인되면 M21 계획으로 바꾼다.
- README의 NAT 관련 문장은 M24가, SSH 호환 문단은 M21이 착지할 때 바꾼다.

## 개정 이력
- 2026-11-13 ADR-0061이 결정 3의 "relay, TURN, 공용 STUN 서버, 중앙 서비스는 들이지 않는다"를 개정했다. 홀펀칭은 그대로이고, 사용자가 켜는 iroh relay route(기본 n0 공용 relay)가 코어에 들어온다. 결정 본문은 고치지 않았다.
